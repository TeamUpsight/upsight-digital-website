# Next steps — beginner version

## 1. Open this project
1. Extract the ZIP to a normal folder such as `Documents\Upsight Website Migration\upsight-astro-migrated`.
2. Open VS Code.
3. Click **File → Open Folder**.
4. Select the extracted `upsight-astro-migrated` folder (the folder that contains `package.json`).
5. In VS Code click **Terminal → New Terminal**.

## 2. Install the project packages
In the terminal, paste:

```powershell
npm install
```

Wait until the command finishes and the prompt appears again.

If Windows says PowerShell script execution is disabled, open the terminal dropdown in VS Code, choose **Command Prompt**, then run:

```cmd
npm install
```

## 3. Start the website locally
Run:

```powershell
npm run dev
```

You should see a local address, normally `http://localhost:4321/`.
Ctrl+click it or paste it into Chrome.

Test these URLs:
- `/`
- `/services`
- `/who-its-for`
- `/process`
- `/about`
- `/case-studies`
- `/case-studies/slice`
- `/case-studies/roadsurfer`
- `/services/cookie-consent`
- `/contact`
- `/health-check`

To stop the local server, click the terminal and press **Ctrl+C**.

## 4. Configure Resend locally so forms can send email
The site itself works without this, but Contact and Health Check email submission will intentionally show an error until the secret is configured.

1. In the VS Code Explorer, find `.dev.vars.example`.
2. Create a copy in the same folder named exactly `.dev.vars`.
3. Open `.dev.vars`.
4. Replace `re_your_key_here` with a valid Resend API key that can send from `notifications@send.upsight.digital`.
5. Save the file.
6. If `npm run dev` is already running, stop it with **Ctrl+C** and start it again with `npm run dev`.
7. Submit the Contact form and Health Check once and confirm both team and visitor emails arrive.

Never upload `.dev.vars` to GitHub. It is already in `.gitignore`.

## 5. Run the production build
Stop the dev server with **Ctrl+C**, then run:

```powershell
npm run build
```

This must finish without an error before deployment.

## 6. Preview the production build
Run:

```powershell
npm run preview
```

Open the local URL shown and re-check the main pages.

## 7. First Cloudflare deployment
Stop preview with **Ctrl+C**.

Login to Cloudflare from the terminal:

```powershell
npx wrangler login
```

A browser window will open. Approve access.

Then deploy:

```powershell
npx wrangler deploy
```

Wrangler will give you a temporary `workers.dev` URL. Test that URL before changing `upsight.digital`.

## 8. Add the production Resend secret to Cloudflare
Run:

```powershell
npx wrangler secret put RESEND_API_KEY
```

When asked for the value, paste the real Resend API key and press Enter. The key will not be committed to the project.

Re-test Contact and Health Check on the `workers.dev` URL.

## 9. Connect the real domain only after staging passes
In Cloudflare Dashboard:
1. Open **Workers & Pages**.
2. Open the `upsight-astro` Worker.
3. Open **Settings → Domains & Routes** (wording can vary slightly).
4. Add **Custom Domain**.
5. Add `upsight.digital`.
6. Add/redirect `www.upsight.digital` if you use the www hostname.

Do not cancel the Manus hosting until the production domain has been tested.

## 10. Production QA
Check on desktop and mobile:
- every page and navigation link
- animations
- Contact submission
- Health Check completion and email
- Calendly links
- GA4/GTM Realtime
- `https://upsight.digital/robots.txt`
- `https://upsight.digital/sitemap-index.xml` or the sitemap URL generated by Astro
- 404 page
- HTTPS
- canonical tags and Open Graph tags

After this passes, the old Manus deployment can be retired.
